How this app is built

Less group chat. More actual plans.
Sign in with Google to start a real event, then enter a ZIP and activity ideas and share an invite. Everyone saves preferences before the group searches nearby venues.
This synthetic run saved 4 responses and chose Coffee and catch-up (demo). Members need no API keys. The demo needs no account.

Pick more than one good time
Members choose Can join, Maybe or Cannot join, pick activities, set a personal spending limit and share needs.
After members opt in, the coordinator can ask the LLM to explain a shared fit. Python checks shared choices; the coordinator still finalizes. Phone access requires secure hosting.

A plan friends can afford
Each person saves a maximum spend. Known venue estimates must fit the event budget and every definite attendee limit.
Maybe stays tentative. Unknown cost needs checking; it is not a promise of affordability.

Suggestions need agreement
Python checks activity consensus, venue votes and budgets. The optional LLM explains only supplied choices and facts.
Every definite attendee must accept the venue. Only the coordinator confirms; AI never books or sends messages.

Real discovery, checked by humans
Simple ZIP tiles use Geoapify Places with a host-managed key. Unknown hours, ratings and prices need checking.
Neo4j and parallel advocates are legacy learning modules. This recording uses fictional places and no external API calls.
